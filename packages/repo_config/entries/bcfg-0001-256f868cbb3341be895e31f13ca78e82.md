## Behavior Config — Repo-Wide

**Push immediately after supplying a viewer link.** Tony reviews entries from the pushed copy only. Once an entry is written and its viewer link is given, push right away rather than asking. Hold off only to batch closely related entries, and say so explicitly if doing that.

**Never modify the Capella model.** This notebook records verification of the model; it does not change it. Model reads go through `capella-fabric` in a separate session. No patches, no pushes to the model repo.

**Pin every verification to a model commit.** A VCP records the model commit it was captured against. Every test result records the exact commit that was checked. A result without a commit is incomplete and should not be written.

**Results are append-only.** Never overwrite a test result. A failed run is evidence. A re-run is a new result entry that references the same test and VCP; the VCP's status and latest-result reference are what change.

**References use real artifact IDs.** Entry IDs are server-generated. Human labels (for example VCP-0001) may appear in titles, but every reference between entries must use the real artifact ID, both in `artifact_refs` and in the body.

**State the intended change before writing.** Before creating a VCP, adding a test, or updating a VCP's status, say what will be written and why. Bulk creation (a block of VCPs) is summarized first and written only on the engineer's go-ahead.

**Distinguish who verified what.** Record the executing agent or model on every result, and the reviewer when there is one. An independent review is a separate entry by a different agent or the engineer, never an edit to the original result.

**Flag, do not guess.** If a requirement parameter is ambiguous or a model object has properties but no linked requirement, skip it and list it in the summary rather than inventing a value.

**Secrets:** never place real tokens or keys in any entry; use placeholders such as `{{GITHUB_PAT}}`.
