## Observation Configuration — Standard Shape and Named Subtypes

**Standard observation shape:** a `##` heading giving the title, a **Date:** line, the body, and a closing **Reference:** footer listing related entries by real artifact ID with a few words on why each matters.

This repo defines two named subtypes of `observation`. Both are written as observations; the title prefix marks the subtype.

---

### Subtype: VCP

**Package:** `vcps`. **Title:** `## VCP-NNNN: <model object name>`. One entry per model object under verification. Changes rarely; revised in place (by `entry_id`) when the object or a requirement changes, so Git holds the history.

Sections, in order:

- **Date:**
- **Model reference:** repo, branch, **commit**, object UUID, object name, phase. The commit is the state this VCP was captured against.
- **Properties:** a table of name, value, units, and any max, min, or nominal value, as read from the object's property value groups.
- **Requirements:** a table of requirement ID, requirement text, parameter name, parameter value. Parameters are explicit, never buried in prose.
- **Tests:** artifact IDs of the tests that verify this VCP (empty at creation).
- **Status:** one of `unverified`, `passing`, `failing`, `stale`.
- **Latest result:** artifact ID of the most recent test result, or `none`.
- **Reference:** edges as typed lines (`targets`, `satisfies`, `verifies`) with real artifact IDs.

Status rules: `unverified` until a result exists; `passing` or `failing` follows the latest result's verdict; `stale` when the latest result's model commit differs from this VCP's model commit, or a requirement parameter has changed since that result.

---

### Subtype: Test Result

**Package:** `test_results`. **Title:** `## RES-NNNN: <test title> — <verdict>`. One entry per execution. **Append-only: never revise.**

Sections, in order:

- **Date:** and run timestamp.
- **Test:** artifact ID of the test executed.
- **VCP:** artifact ID of the VCP verified.
- **Model commit:** the exact commit checked. Required.
- **Executed by:** the agent or model that ran it, or the engineer.
- **Measured values:** name, value, units.
- **Checks:** a table of criterion, result (`pass` or `fail`), margin.
- **Verdict:** `pass` or `fail`.
- **Reviewed by:** `none` at write time. Independent review is a separate entry that references this one.
- **Reference:** typed lines (`executes`, `evidences`, `against`) with real artifact IDs.

---

### Subtype: Review

**Package:** `test_results`. **Title:** `## REV-NNNN: review of RES-NNNN — <confirmed | disputed>`. Written by a different agent or the engineer than the one that executed the result. Records what was checked, the verdict, and any disagreement. Typed reference line: `reviews` with the result's artifact ID.

---

**Recognizing further subtypes:** if a new repeated shape appears (for example a block-run summary), propose adding it here rather than inventing a one-off.

**Reference:** `candidate_playbooks`/OBS-0020 in `knowledge_partner` (data model and edge vocabulary these shapes implement).
